一、这是什么

一句话：把跨境 Listing 的两件苦活——配图与文案——从"凭感觉"变成"有规则、可检查"。

它解决三个具体问题：

问题常见做法这个工作台的做法
配图不知道怎么写 Prompt抄别人的提示词，出来的图看着像但卖不动先判断"这是什么产品、想解决什么"，再从 25 个场景模板里选一个，套上固定的视觉规则，生成一段可直接用的 Prompt
Listing 写完不知道合不合规发上去被改、被压搜索，事后才发现28 条规则逐条机械判定，每条都附"为什么定这条"和"口径来源"
不知道竞品在打什么词靠猜，或者买付费工具抓公开榜单 → 本地算关键词权重 → 生成文案提示词；也可以直接粘贴竞品文案做覆盖度对比

它不做什么（这点更重要，避免期待错位）：

  • 不代替你做选品和定价决策；
  • 不自动改你的线上 Listing，也不自动投放；
  • 不自己算、也不估搜索量——宁可给一个覆盖矩阵，也不编一个价值分；只有你导入第三方导出表时才显示搜索量，并标明"来自哪个文件"；
  • 不做账号体系、不做云同步：所有产物留在你自己的电脑上。

四、创作台：把一句话变成可用的图片 Prompt

4.1 基本操作

在底部输入框里描述你的产品和需求，按「发送」。例如：

  • 帮我生成一款蓝色蓝牙耳机的白底主图
  • 给这件亚麻衬衫做一张场景化生活图，9:16
  • 陶瓷马克杯，做一套详情页

系统会依次完成下面几件事，并把每一步的依据显示在对话里（不是黑箱）：

  1. 识别上下文 —— 这是什么品类、这句话想解决什么（卖点？场景？信任？）、有没有上传参考图；
  2. 匹配模板 —— 从 25 个模板里选一个，同时告诉你"依据是什么"和"还有哪些并列候选"；
  3. 诊断转化驱动力 —— 判断这句话偏"视觉冲击 / 功能解释 / 信任建立"哪一类；
  4. 套用视觉风格锁（Style Lock） —— 固定配色、光线、字体、质感，保证一套图看起来是同一个品牌；
  5. 组装 Prompt —— 按固定结构拼出可直接使用的提示词；
  6. 机械自检 —— 检查颜色是否写成色值、产品占比、留白、否定清单、画幅、角度是否齐全；
  7. 输出简报 —— 一段人话说明 + 一段可复制的 Prompt。

4.2 六条视觉铁律

生成 Prompt 时，这六条是硬约束，缺一条自检就会报出来：

#铁律为什么
1颜色必须写成十六进制色值"高级灰"每个人理解不同，#8A8A8A 不会跑偏
2产品占画面比例必须给数字不写比例，模型会把产品缩成一个小角落
3留白必须显式声明留白是给文案和平台元素的位置，不写就会被填满
4必须有否定清单只写"要什么"不够，还得写"不要什么"（多余文字、水印、多件产品…）
5必须预留平台空间国内电商要留价格浮层位；亚马逊首图反过来——整幅不许有任何叠加
6三层信息架构（主标题 / 副标题 / 说明）信息有层级，图才不像字帖
🔴 亚马逊主图是例外：平台法规优先于设计口径。首图要求产品占 85–100%、纯白底、禁止任何文字与叠加——这跟"产品占 35–40% + 留白 45%"是两套互相矛盾的标准，所以系统对首图单独走一套法规层，不会把两套数字硬拼在一起。

4.3 它会告诉你"为什么选这个模板"

自动匹配不是猜的，判定顺序是：

  1. 你说出的模板名 / 别名（比如"隐形模特""平铺""买家秀"）；
  2. 关键词命中（产品的品类词、场景词）；
  3. 上下文推断（品类 + 转化驱动力 + 有没有参考图）；
  4. 都没有才走兜底，并且如实标注"这是兜底，不是匹配上了"。

所以如果结果不对，通常改一句描述就能换到另一个模板——对话里会列出并列候选，可以据此调整措辞。

4.4 两种产出：Prompt 还是真图

情况你会得到说明
没配图片 API一段完整 Prompt复制到任何生图工具（Midjourney、即梦、SD 等）都能用
配了图片 APIPrompt + 真实图片图片存到本机 data/gen/，同时出现在「图片库」
上传了参考图图生图 Prompt 或图生图结果系统会先分析参考图；分析失败会明确告诉你"未参考原图"，不会假装用了

4.5 画幅怎么指定

直接写比例即可，支持 9 种：

比例像素适合
1:11024×1024平台主图、社媒方图
4:31024×768横版展示
3:4768×1024竖版展示
3:21536×1024横版海报
2:31024×1536详情页长图
16:91536×864Banner、横屏
9:16864×1536抖音 / 小红书 / Story
4:5819×1024Instagram 竖图
5:41024×819横版方图

也可以说人话：竖版→3:4、横版/海报/banner→16:9、小红书/抖音/社媒→9:16、详情页→2:3、主图/方图→1:1。

⚠️ 系统只认上表里的比例。写 10:30 这种数字不会被当成画幅（那是时间），写 7:5 会被忽略并回落到默认的 1:1。

同步接口会"吸附"画幅，并如实告诉你：

OpenAI 兼容的同步生图接口只接受三种像素（1024×1024 / 1536×1024 / 1024×1536）。所以当你请求 16:9 时，
系统会把它吸附成最接近的 1536×1024，并在消息里明确写一行：

画幅已吸附：请求 16:9（1536×864），同步接口只接受 1024x1024 / 1536x1024 / 1024x1536，实际发送 1536x1024，成图比例与请求不同
  • 1:1 / 3:2 / 2:3 本来就等于白名单里的三种，不会吸附，也不会出这行提示；
  • 异步接口（apimart 这类收比例字符串的）不做吸附，原样发 16:9；
  • 设置里把「同步模式」改成「自由」时，按上表原样发像素——能不能被接受取决于你的接口，报错就是它不支持。
为什么不做"请求什么就给什么"：客户端悄悄换画幅和悄悄不换一样糟。宁可多一行字，也不让用户拿到一张比例不对的图还以为是自己的问题。

4.6 「整套」模式

点输入框右侧的「整套」（或在消息里说"整套 / 一整套图"），会一次规划 14 条 Prompt：

  • H1–H5：5 张主图组（白底主图、细节微距、场景图、使用前后对比、促销海报）；
  • D1–D9：9 张详情页（信息图、对比图、规格说明等）。

如果这句话被识别为"亚马逊主图需求"，会额外多一条 M0（合规首图），共 15 条。

每条都带独立的构图口径与角度，不是同一段 Prompt 复制 14 遍。

规划 ≠ 出图，界面上会把这件事说清楚：

  • 简报里写的是「14 条 Prompt 逐条核过」，不是「14 张图核过」——核的是 Prompt，不是成图；
  • 如果配了生图 API，消息里会出现一张整套出图卡：按顺序逐张生成、每张一次独立调用、

可随时停、某张失败不中断（失败项单独列出原因）；

  • 开跑前会要你确认，并明确写「按你自己的接口计费，本工具不代你估算金额」；
  • 只有一条 Prompt 时不会出现这张卡（那张图会直接出）。
🔴 别把「14 条 Prompt」读成「14 张图已生成」。规划是零成本的，出图是 14 次计费调用。

4.7 说"不要出图"会怎样

系统会看同一分句里的否定词。所以：

  • 先看文案，这款暂时不要出图 → 只给 Prompt，不调用生图接口；
  • 不要加文字，直接出图 → 正常出图（"不要"修饰的是"文字"，不是"出图"）。
这条看起来小，但很关键：判断错会导致「说了不要还是扣了 API 费用」或者「说了要却没反应」。

4.8 使用注意

  • 一次说清一个需求。一句话里塞三个场景，系统只会选一个模板。
  • 产品名要具体。"杯子"不如"350ml 双层不锈钢马克杯"，后者能匹配到更准的模板与构图。
  • 不要指望它替你写卖点。它负责构图与视觉规则，卖点来自你对产品的了解。
  • 输入框旁的「＋」是随机示例，不知道怎么写时可以先点一下看格式。
  • 停止按钮只中断当前这一轮，已生成的结果不会丢。

六、图片库：生成结果都在本机

  • 列出的是本机磁盘上的真实文件（data/gen/），关掉浏览器也还在；
  • 支持单张下载、删除，以及一键复制全部路径；
  • 顶部有按文件名过滤的搜索框：边打边筛，纯前端过滤、不重新请求；筛不到时给「清空筛选」的出路（图片没有被筛掉，只是没匹配上）；
  • 「复制全部路径」跟随当前筛选——筛出 5 张，复制的就是这 5 条；
  • 「打包下载全部」会打成一个 zip：上限 65535 个文件 / 4 GB，超出会直接报错（不会产出一个坏包）。注意 zip 始终打包 data/gen/ 全部文件，不受搜索框影响（界面上会提示这一点）。
图片不会上传到任何服务器。你在「图片库」看到的，就是你电脑里的文件。
⚠️ 删除是直接删本机文件、不进回收站，确认框会明确提示，删了无法恢复。
⚠️ 如果在界面上看到"本地服务没在跑"，图片并没有丢——启动服务后点「刷新列表」即可。

七、文案与质检：一个 Listing 从写到查

这个视图现在是两栏 + 五个抽屉，不再是七张卡平铺：

  • 左栏「产品与语料」＝ 原 ① 产品输入 + ② 关键词挖掘（合并成一张卡的三段：我的产品 / 竞品在说什么 / 取词）
  • 右栏「文案编辑」＝ 原 ④ 可编辑字段（五个字段做成 tab）+ ⑤ 质检结果（同一张卡的下半部）
  • 页头＝ 原 ③ 生成草稿的两个动作（生成草稿 / 生成并质检），随时可点，不再占一整张卡
  • 页脚五个抽屉（默认收起）＝ ⑥ Rufus 准入检查 / ⑦ 竞品榜单抓取 / ⑧ A+ 模块骨架 / ⑨ 批量质检 / 平台限制与规则集

推荐路径：填资料 → 取词 → 改文案 → 跑质检；Rufus 与竞品抓取按需展开。

7.1 ① 产品输入（左栏 · 我的产品）

字段填什么注意

7.2 ② 关键词挖掘（左栏 · 竞品在说什么）

把竞品标题 + 五点 + 类目页文案粘进来（多个竞品用一行 --- 分隔），点「挖掘关键词」。

它做的是词频统计，不是模型生成：

  • 切 1–3 个词的组合，去掉停用词，按"覆盖率 / 出现位置 / 精准度"打分；
  • 只保留在至少 2 个竞品里出现的词（只出现 1 次的是噪声）；
  • 可以按语种切换停用词表（英 / 德 / 法 / 西 / 意 / 荷 / 日），否则德国站标题里的 mit / für / und 会被当成卖点词；
  • 日语不做分词，界面会明说——不引入词典依赖，避免切出一堆无意义的碎片。
⚠️ 这不是搜索量。词频只说明"竞品在反复用"，不说明"有多少人在搜"。界面上也会标注这一点。

「多竞品对比」会按"几个竞品用到这个词"分成两类：全类目共识词（几乎人人都在打，必须覆盖）与差异化词 / 品牌词（少数人在打，是机会或必须避开）。

还有一块是每周词库：点「载入本周词库」，读的是定时任务每周抓好的快照（词根 → 真实搜索建议词 + 榜单 ASIN）。
它先给你一张体检卡，而不是直接甩一堆数字：这份数据新不新（新鲜 / 偏旧 / 过期 / 没有，四档）、
站点有没有实测过、价格字段全不全、上次采集成没成、有没有被截断 —— 任何一条不理想都会单独写一行，并说明该怎么办。
下面是三个排序（词根命中 / 新词优先 / 字母序），再下面是「把前 30 个词填入关键词框」。

为什么非要把"不新 / 不全"写在脸上：数据看着漂亮但其实是三周前的，比没有数据更危险 ——
你会拿它去下判断。所以这一块刻意做成"先说哪里有毛病，再说有哪些词"。

7.3 ③ 生成草稿（页头两个按钮）

点「生成草稿」，按规则填出一份结构合规的 Listing。

⚠️ 这是填空式草稿，不是文案创作。它的价值是省掉从零排版的时间：字段齐全、不超限、硬规则全过。措辞必须人工改写——直接发布会有浓浓的模板味。

「生成并质检」= 生成后立刻跑一遍 28 条规则。

7.4 ④ 可编辑字段（右栏 · 五个 tab）

五个字段：标题、Item Highlights、五点、Search Terms、商品描述。标题上方有三个计数条，实时显示：标题 / 125 / 两段合计。

三种计法不要混：

  • 标题、Item Highlights、五点、描述 —— 按字符；
  • Search Terms —— 按字节（中文、emoji 占多个字节，250 字节很快会用完）。

导出有三种形态，用途不同：

按钮得到什么用在哪
导出后台字段逐字段、可逐个粘贴的文本卖家后台是一个字段一个框，整段 JSON 填不进去
导出 Flat File CSV按官方属性名排好列往批量表里搬数据。不是可直接提交的官方模板，各类目列名不同
导出质检报告 JSON完整的规则命中结果留档、给别人复核
如果 Item Highlights 超了 125 字符，系统会按逗号整段移除末尾短语，并明确告诉你"挤掉了哪几句"——不会静默截断。

7.5 ⑤ 质检结果：28 条规则（右栏下半部）

规则分两档：

  • P（必须改）：平台明文规则或入口级风险，发布前应清零；
  • C（建议改）：影响可读性或转化，不影响合规。
编号档检查什么
P1P标题超过 75 字符（media 类目除外）
P2P标题含促销词 / 最高级 / 平台徽章词（free shipping、best seller、Amazon's Choice）
P3P标题含特殊符号（`! ? $ _ \< >` 等）
P4P标题 71–75 字符：离硬顶不足 5 字符，再补一个词就越线（项目自定的保守口径）
P5P标题大面积全大写（字母中大写占比 > 60%）
P6P疾病 / 医疗声明、农药抗菌声明、绝对化保证性用语

P8P五点里写价格 / 促销 / 物流信息（五点是产品属性位）
C9C五点没有用"大写引导词 + 冒号"开头（影响扫读，不影响合规）

C11C标题与 Item Highlights 内容重复（官方要求"每一条都要补充新信息"）
C12C疑似电话号 / 站外社交平台名（软规则，避免误伤 350-500-1000 这类规格）
C13C标题里同一个词反复出现（75 字符时代更不划算）
C14C标题含主观夸赞（HOT ITEM、BEST QUALITY 之类）

读结果的方式：未命中的规则也会列出来，让你看见"检查过什么"。每条命中都带 为什么定这条 与 口径来源，可以自己判断是否接受。

规则里刻意保留了一些"软判定"。例如 C12 只挑形状像电话的串，因为硬禁会把规格数字全打成违规——误报多了，人就不信质检结果了，那比漏报更糟。

7.6 关键词覆盖度分析

用你填的"自定义关键词"和粘贴的竞品语料，逐词检查它落在标题 / 五点 / 描述 / 后台词的哪几处。

输出不是分数，是一张矩阵：哪个词全覆盖、哪个词只出现在五点、哪个词一个字都没提。

它只测文本覆盖，不是搜索排名，也不是搜索量。

7.7 ⑥ Rufus 信息架构检查（准入层）

这一层和 ⑤ 的质检问的不是同一个问题：

  • ⑤ 问：文案合不合规？
  • ⑥ 问：能不能被 Rufus 纳入结构化比对？

Rufus / Alexa for Shopping 的工作方式是先做结构化比对，再决定要不要引用你的文案。所以字段缺失、事实矛盾、单位打架，都会让你的商品在"被引用"这一步就出局。

5 组规则：

组检查什么典型问题
R1属性完整性官方必填字段空着 → 进不了最细的浏览分类
R2跨字段事实一致性标题说纯棉、描述说纯涤纶；标题 2 件、五点 3 件
R3单位制一致性同一维度同时用英制和公制，比价时取到互相打架的数值
R4买家高频问题覆盖80 条类目高频问题，listing 里找不到答案句
R5图内文字未文本化规格 / 成分只印在图上，机器读不到，等于不存在

使用要点：

  1. 必须选"产品类型"，否则 R1 与 R4 会全部跳过——不选就不替你猜；
  2. 图内文字要人工粘贴（每行一条）。系统不做 OCR、不猜图上内容；留空则 R5 整条跳过；
  3. 跳过项一定可见并写明原因。把跳过藏起来，等于让你以为全通过；
  4. 结论只有一条，来自引擎统一计算，界面不会另写一套"通过 / 不通过"。

7.8 ⑦ 竞品关键词 → 文案提示词

从亚马逊 Best Sellers 公开榜单页实时抓取竞品标题，本地算权重，再生成可复制的文案提示词。

抓取范围：8 个站点（美国、英国、德国、法国、日本、加拿大、意大利、西班牙）× 20 个类目（玩具、宠物、电子、家居厨房、厨房餐具、运动户外、美妆个护、健康家居、母婴、办公、家电、汽车、艺术手工、乐器、服饰鞋包、电子游戏、图书、食品杂货、工业科研、工具五金），还可以再选子类目。

关键词权重公式：

权重 = 覆盖率 × 50% + 位置 × 30% + 精准度 × 20%   （满分 10）

只保留在至少 2 条竞品标题里出现的词。

生成提示词：可以选 5 类——竞品标题拆解、标题 + 产品亮点、五点描述、后台搜索词、多语言本地化。提示词里只带工具已经算好的结论，并明确要求模型"直接采用、不要重算"。

坐标说明：

  • 数据源是公开榜单页，亚马逊改版时会抓不到——会如实报错，不会拿假数据凑；
  • 有 10 分钟缓存，别高频轮询；
  • 原「关键词搜索」路径（/s?k=）已被亚马逊封锁，本工作台不提供；
  • 抓不到时，仍可把竞品标题手动粘到 ② 卡里，本地算法照样工作。

7.10 导出体检报告（单文件 HTML）

点「导出体检报告」，得到一个 .html 文件：双击就能打开、可以直接发微信、也能用浏览器打印成 PDF。

里面包含：

八、数据采集：把亚马逊页面变成结构化数据

8.1 方式 A · 书签脚本（推荐）

同一个书签，自适应两种页面：

  • 在商品详情页点 → 抓单条完整数据（标题、五点、规格、BSR、主图）；
  • 在搜索结果页点 → 一次抓整页商品（标题、价格、评分、评论数、ASIN）。

安装步骤：

  1. 把页面上的「抓取亚马逊商品」按钮拖到浏览器书签栏（或右键复制链接，新建书签后粘贴到网址栏）；
  2. 打开亚马逊商品详情页，或搜一个词停在搜索结果页；
  3. 点这个书签 → 结构化数据进入剪贴板；
  4. 回到「数据采集」页，粘到"方式 B"的框里，点「解析」。
书签脚本是自包含的，不依赖本应用是否打开，也不会上传任何数据。

8.2 方式 B · 粘贴内容

自动识别四种输入：

  • 书签脚本产出的 JSON（详情页）；
  • 书签脚本产出的 JSON（搜索结果页，整页商品表）；
  • 页面源码 HTML（右键"查看网页源代码"后全选复制，搜索结果页也认）；
  • 纯文本（按标题 / 五点结构尽量解析）。

解析结果会自动存进「本地产物」，刷新不丢；也可以点「导出 JSON」单独带走。

8.3 为什么不做服务端爬虫

这是刻意选择，不是没做完：

  • 服务端直抓会被反爬与 TLS 指纹拦住，成功率低且不稳定；
  • 即使用代理抓到了，返回的价格 / 评论数也未必等于用户实际看到的（地区、登录态、AB 实验都会影响）；
  • 出错时最糟的是"看起来成功了，数据其实是错的"。

所以竞品数据走用户侧采集：你看到什么，就抓什么。

九、本周词库：每周抓来的词，怎么用

侧栏 Listing → 本周词库。它是独立一页，只干一件事：告诉你这份词库新不新、全不全、有哪些词。

9.1 页面只有三块

区块内容什么时候看它
四格体检条词 / ASIN / 本周新增 / 采集日期（带"几天前"）进来先看这四格。日期不是本周，下面所有结论都要打折扣
筛选行搜词面（部分匹配）+ 三种排序（词根命中 / 本周新词 / 字母序）找某个词，或只看这周冒出来的

9.2 三个必须说清的口径

  1. 「分不出」不是 0。 第一次采集（或没有历史投影）时，「本周新增」那一格写「分不出」——

意思是没算过，不是"这周没有新词"。下一周再采一次就有了。

  1. 看到的是前 500 条。 词库通常两千多条，接口一次最多给 500 条；页面上会直说"共 N 条，这里列前 500 条"。

想缩小范围用搜索，别以为词库只有 500 条。

  1. 陈旧要认。 超过 10 天标黄提示；超过 21 天直接说"别当本周数据用"。

站点若不是 US，会额外说明"抓取规则没实测过，字段可能缺"。

9.3 把词送进文案页

点右上角 送进文案页：把当前筛选结果的前 30 个词填进「文案与质检」的关键词框，并自动切过去。
只填关键词框，不覆盖标题与五点 —— 这一步的语义是"把词带过去"，不是"改文案"。

9.4 这份数据是怎么来的

定时任务每周跑一次（GitHub Actions，或本地 node tools/collect-keywords.mjs）：
194 个词根 → 抓搜索建议 → 再从类目榜单补 ASIN。产物是 data/keywords/latest.json；
界面、GET /api/keywords、MCP 的 keyword_snapshot 三处读的是同一份文件。

任务没跑过时，这一页不会只说一句"加载失败"，而是直说"暂时没有词库"，并交代上次采集怎么了
（失败原因 / 上次成功时间 / 从未跑过）—— 这才是能照着修的信息。

9.5 这一版多出来的五件事（都默认收起，页面不会变复杂）

新增的能力全放在这一页的折叠区里，不另开视图，也不往首屏塞卡片。想用再点开。

折叠区解决什么没有数据时怎么办
用本周词库做覆盖度体检原来「送进文案页」只把词填进框，不判断。现在直接算：本周热词里，我的 Listing 一个字都没提的有几个，每条还标出是哪个词根带出来的没写 Listing 就说「先去写 Listing」，不给 0
本周 vs 上周两列并排：新进 / 回归 / 掉出的词。回归词单独算，不混进「新增」里糊弄人只有一份快照时明说「暂时没法对比」
ASIN 榜单变动「本周新进榜单 7 个、掉出 5 个、名次动了哪几个」。三个集合互不重叠没有历史投影就说「暂无」，不编 0
词根管理194 个词根以前写死在源码里，改一个要动 JS。现在 data/keywords/roots.json 就是运营可改的覆盖层：加、删、改名都在页面上，并反馈「这个词根本周带出多少词」「连续 0 命中，建议替换」覆盖层读坏了会退回基线并说明，不中断采集；非法词根会列进「被拒」并给理由，不静默
导出 CSV词表 / ASIN 两个导出，带 UTF-8 BOM，Excel 直接打开不乱码；字段里有逗号、引号、换行都按 RFC 4180 正确转义没有快照时导出的是只有表头的空表，不是一份假数据

还有一处小改动：站点下拉里，除了 US 以外的站点都标 ○ 未实测，选中时会提醒「类目映射可能不准，仅 US 经过实测」。
这是「可见但不承诺」—— 数据结构已经按一站一文件留好，将来开站是一个参数的事，但现在不假装跑过八站。

10.1 快照对比：同一件商品，前后两次抓的差在哪

同一件商品抓过两次以上时，在"采集"类记录前面勾两条，再点「对比快照」：

  • 按时间排前后，不是按你勾选的顺序——先勾新的再勾旧的，不会把"改前/改后"读反；
  • 比 9 个文本字段：标题、品牌、价格、星级、评论数、类目排名、五点、规格、描述；
  • 五点/规格这类列表会给增删明细（新增 1 条 / 删掉 1 条），不是只回一句"变了"；
  • 搜索页对搜索页，按 ASIN 集合比谁进榜、谁掉榜（20 个商品逐字段摊开没人看得下去）。

它不会做的事（界面上也写着）：

  • 不猜对方为什么改，也不评价改前改后哪个更好；
  • 两份记录的 ASIN 不同时，会在最上面直接写「这不是同一件商品的前后对比」；
  • 两份里缺 ASIN 时，会写「无法确认是同一件商品」，不假装是同款；
  • 主图、A+ 内容、变体结构不在比较范围内；价格与排名本身还会随地区、登录态、时间变化。

十三、常见问题

Q1：打开页面是空白 / 只有标题。
多半是双击了 index.html。请用 node server.mjs 启动后访问 http://127.0.0.1:8787/。

Q2：点了发送，只给了 Prompt，没有图。
三种可能：① 没配图片密钥；② 消息里没有"出图 / 生成图片"之类的词；③ 本地服务没启动（此时是纯离线模式）。看右上角模式标签：写「本地编排」就是没连上服务。

Q3：出图很慢，是不是卡住了。
异步接口通常要几十秒到两分钟：提交后先等 12 秒，再每 4 秒轮询一次结果。界面会显示进度，点「停止」可中断当前轮。

Q4：抓竞品榜单报错。
亚马逊改版或临时限流都会导致抓不到。10 分钟后再试，或换类目；也可以手动复制竞品标题粘到 ② 卡，本地算法一样能用。系统不会用假数据顶替。

Q5：标题为什么只能 75 字符？我记得是 200。
2026-07-27 起普通类目压到 75（含空格），media 类目仍是 200。另外新增了 Item Highlights 125 字符，两者合计 200。旧的"标题 200"说法已经过时。

Q6：Search Terms 明明没写几个字，怎么就说超了。
它按字节算，不是字符。一个中文字通常 3 字节，250 字节大约只有 80 多个汉字。

Q7：Rufus 检查里好几项显示"跳过"，是不是坏了。
不是。没选产品类型、没填图内文字、类目不适用，都会如实跳过并写明原因。跳过 ≠ 通过，这是刻意的设计。

Q8：数据存在哪？换电脑怎么办。
生成的图在 data/gen/，其他产物在浏览器 IndexedDB。换电脑：拷 data/ 目录 + 在「本地产物」导出 JSON 后在新机器导入。密钥要重新配。

Q9：会不会把我的数据传到网上。
不会。只有三种情况会出网：调用你配置的生图 / 对话接口、抓取公开榜单、以及你主动点开的第三方链接。密钥不出本机。

Q10：能不能几个人一起用。
当前是本地优先的单机工具，没有账号体系。多人协作需要自己搭共享目录 + 反向代理，不在本项目的设计范围内。

Q11：能不能直接连我的店铺后台改 Listing。
不能，也不打算做。改线上内容是资金与合规风险最高的操作，本工具只做"生成 + 检查"，提交由你自己完成。

Q12：为什么没有搜索量 / 竞争度分数。
真实搜索量来自付费数据源（Helium 10、Brand Analytics 等）。拿不到就编一个分数，会让决策建立在假数据上。本项目选择给覆盖矩阵与权重，并明确标注"这不是搜索量"。

十四、已知限制（先说清楚）

  1. 中文部分能力有限：Rufus 规则里的单位识别对中文单位支持不完整；Listing 规则主要按英文平台口径设计。
  2. 不做 OCR：图上的文字必须人工粘贴，系统不解析图片内容。
  3. 不接付费数据：没有搜索量、没有竞品销量估算、没有广告花费分析。
  4. 榜单抓取依赖页面结构：亚马逊改版会失效，届时需要更新选择器。
  5. 模板数据是外部来源：25 个模板来自公开参考项目，本项目只消费不改写；模板本身的表达习惯未必适合所有品类。
  6. 规则是启发式：28 条规则覆盖高频问题，不是平台审核的全部；P 档清零也不等于一定过审。
  7. 浏览器存储有上限：产物每类 60 条，超出淘汰最旧；清站点数据会清空。
  8. 没有多用户 / 权限 / 审计：定位是个人或小团队的单机工具。
  9. 只在 Chromium 内核验证过：Chrome / Edge 可用；Safari 与 Firefox 未做端到端验证。
  10. 界面上有少量"多语言"是提示词层面：生成的 Prompt 是英文（生图模型对英文更稳），不是界面多语言。
  11. 语种支持是不对称的：词频与停用词支持中/英/德/法/西/意/荷/日 7 套；但利益词判据（C3）与 Prompt 输出只有中文、英文两套。日/德/法等语种的五点在质检里会被标成「跳过·未判定」——未判定不等于通过，也不等于不合格。另外：纯汉字的日文标题与中文无法区分（会按中文处理），德语复合词（KaffeetassenSet）不会被拆开。
  12. 只读演示版不能写：线上那版把 6 条写路由关了（写配置、上传、生图、识图、对话模型、删图库），前端也会提前禁用按钮而不是等你点了才报 403。它只出 Prompt，不出图。
  13. 资源上限是硬闸门：打包下载最多 300 个文件 / 单张 40MB / 合计 300MB；上传只认 PNG / JPEG / GIF / WebP 四种（按文件头魔数判断，不看你声明的类型）；竞品榜单一次最多抓 3 页。
  14. 「主图禁 AI 生成」与「AI 图要打 XMP 标」标的是「待核实」：前者由亚马逊两条官方要求（主图须为摄影作品、图片须如实代表商品）合并推论得出，后者来自 IPTC / C2PA 行业规范，亚马逊是否强校验没有拿到官方原文。所以这两条在 Prompt 里写成"交付前核对"，不写成"平台规定"。
  15. MCP 那部分同样没有关键词数据：接进 AI 助手之后，判断能力和网页版完全一样（同一份代码），但搜索量、ABA 排行、关键词库依然没有。这不是没做完，是边界（数据要账号级 Token，不能随代码分发）。
  16. MCP 只在本机跑：它是本地子进程模型，没有网络端口，也就没有对外暴露面。不要把它挂到公网 HTTP 上给外部调用，那需要另加鉴权，本项目没做。

十五、接进你自己的 AI 助手（MCP）

这是给「不想开网页、想在自己常用的 AI 客户端里直接用」的人准备的。

本工作台带一个 MCP server。MCP 是一个通用协议，Claude Desktop、Claude Code、Cursor、VS Code、Codex、WorkBuddy 都支持。接上之后，你在对话框里说「帮我检查这条标题」，AI 就会来调这里的规则，结果和网页里一模一样（因为是同一份代码，不是另写一套）。

15.1 先说清楚它给什么、不给什么

✅ 给拿文案去判断：28 条规则质检、上传前还差什么、关键词覆盖到没覆盖、图片 Prompt 怎么拼、两次抓取的差异
❌ 不给关键词数据：没有搜索量、没有 ABA 排行、没有关键词库、没有 ASIN 榜单

这一条必须先讲，否则接上去第一句话就会失望：

你问它「ceramic mug 这个词有多少搜索量」——它答不出来，它没有这个数据。
你问它「我这条标题哪里会违规、还差什么才能上架、我埋的词漏了哪些」——它逐条给结论和依据。

想要搜索量 / 反查排名，得另外接数据源（卖家精灵、西柚洞察）。那两家的数据要你自己的账号 Token，谁用谁配，没法随代码发给别人 —— 这也是这里自己做 MCP 的原因：判断层能跟着代码走，数据层不能。

15.2 三步接上

第一步：确认电脑上有 Node.js 20.15 或更高（命令行敲 node -v）。不需要安装任何东西，这个项目零依赖。

第二步：把项目文件夹放到一个固定位置，记住它的完整路径。

第三步：把下面这段写进你用的客户端的配置文件，把 <项目路径> 换成刚才那个路径（用正斜杠 /，Windows 也一样）：

{
  "mcpServers": {
    "listing-studio": {
      "command": "node",
      "args": ["<项目路径>/mcp/server.mjs"]
    }
  }
}

mcp/clients/ 文件夹里有 6 份现成的，按你的客户端挑一份复制即可：

看到结尾 示例全部通过 ✓ 就说明服务端本身没问题 —— 那么"接不上"就一定是客户端配置的事（键名写错 / 没重启 / 不在 Agent 模式）。

15.3 能做什么（八个工具）

你说的话AI 调的工具你会看到

最后一个是唯一的联网工具。不想让它联网，启动参数加 --no-net，它就一个外部请求都不发。

15.4 三个必须知道的坑

  1. 「跳过」不是「通过」。 字母太少的标题判不了全大写、没填品牌判不了品牌堆砌 —— 这些是「没查」，不是「查了没问题」。结论里会明写这一点，做自动化时别只看「命中 0 条」。
  2. 建议词 ≠ 搜索量。 amazon_suggest 只说明「有人这么打字」，不说明有多少人搜。
  3. 覆盖度 ≠ 排名。 关键词覆盖只回答「这个词有没有出现在我的文案里」，覆盖上去不代表排名会涨。

15.5 接不上怎么办

现象多半是怎么办
客户端里看不到这个工具路径写成了相对路径改绝对路径
显示 0 个工具Node 版本太低node -v，要 ≥ 20.15
连上就没反应路径写错 / 文件被移动命令行手动跑 node mcp/server.mjs，能打出 ready 才是好的
搜索建议偶尔报错亚马逊风控正常，工具会如实报错，不会假装成功

不想改配置文件：一个 URL 接上（P0-B2）

原来的 stdio 方式要写一份带绝对路径的客户端配置，路径写错就「工具不出现」且没有报错。
现在多一条路：

node mcp/http.mjs        # 或 npm run mcp:http

它只监听 127.0.0.1:8790，客户端填 http://127.0.0.1:8790/mcp 这一个 URL 就行。
启动时生成的密钥在 data/mcp-setup/token.txt，优先用 Authorization: Bearer <token> 传；
只有那种「只能填一个 URL」的客户端才降级成 ?token=，且这个降级有 12 小时有效期并拒绝带 Referer 的请求。

四道门一道不少：只绑回环、Host 白名单（防 DNS rebinding）、跨站 Origin 一律 403、Bearer 校验；
GET /mcp 回 405 —— 八个工具都是单轮问答，不需要服务端主动推流。
它和 stdio 版共用同一个消息处理函数，所以两边 tools/list 出来的工具完全一致，不会出现「网页能用的工具命令行没有」。

⚠️ 带 ?token= 的 URL 会进浏览器历史、Referer 和日志，别截图发出去。
能填 header 的客户端一律用 header。这一条不是洁癖：本机 HTTP 服务对浏览器天然可见，
少一道 Origin 校验，任何一个恶意网页都能拿你的浏览器去调本机工具。

现在每个工具还带了 annotations（只读 / 非破坏 / 幂等 / 是否访问外部世界）与 outputSchema，
结果里既有原来的文本 JSON，也有 structuredContent —— 老客户端照常读文本，新客户端可以直接拿结构。
参数校验也改成了表驱动：传错类型会明确说「应为 number」并带上上限值，不再笼统报一个「参数错误」。

详细说明（含 JSON-RPC 示例、排错表、边界清单）见项目里的 mcp/README.md。

16.4 归一为什么是"猜字段"

同一条数据，不同工具可能叫 keyword / keywordText / searchTerm，搜索量可能是
searches / searchVolume / monthlySearch，还可能写成 12.3K 这种展示值。
对方改版也不会通知我们。

所以归一层做的是有原则的宽容：认几个常见字段名，认不出就返回 0 条并说明为什么，
同时把"这次用的是哪些字段"原样回报（界面上显示成 keyword→term · searches→volume）。

  • 猜对了：你能看见它怎么猜的，可以放心用；
  • 猜错了：返回 0 条 + 一句原因，而不是给你一份假数据。

第一次接上一个新工具，请先点「调用」核对一次字段，再点「导入」。

16.5 四条边界

  1. 只连白名单里的端点：URL 是服务端的一个常量表，请求体里没有 URL 字段 ——

否则这个接口就成了通用跳板（内网地址、云元数据地址都能被塞进来）。

  1. 不代付、不内置密钥：谁用谁配。想在团队里共享，请自行约定的方式，本项目不存共享凭据。
  2. 只取数，不代操作：取回来的是词表，不会替你去投放、调价、改 listing。
  3. 失败要能分清是谁的错：HTTP 401/403 会明说"鉴权失败——检查密钥是否有效/是否过期"，

超时会带毫秒数，对方返回不合协议会说"不是标准 Streamable HTTP 帧"。不笼统报"失败"。

十八、健康分 / 评论分析 / 成图体检 / 历史快照

这四块是 2026-11 新增的，共同点是都能给一个数或一张图，而且这个数/图能被验算。
它们没有新增独立视图 —— 都挂在原有页面的下游（质检结果里、采集页里、图片库里）。

18.1 Listing 健康分（文案与质检页）

28 条规则 + 5 组信息架构 + 覆盖度，收成一个 0–100 的分。

维度权重依据
合规硬门槛26所有 P 级规则 + 需要举证的软规则
信息架构18Rufus 准入层（字段齐 / 事实自洽 / 单位不混 / 高频问题有答案）
关键词覆盖14候选词在标题/五点/描述/后台词的加权覆盖（要先跑一次覆盖度分析）
标题可读性10C 级标题规则
五点说服力10C 级五点规则
Item Highlights8新规第二段是否使用、是否重复标题

长度预算7有上限的字段里，既没超限也没空的占比

三条硬规则，界面上一眼能看到：

  1. 硬规则命中 → 封顶 55（D 档）。不给"改改措辞还能拿 80"的错觉。
  2. 缺数据的维度不算分。没跑覆盖度分析时，"关键词覆盖"显示 — / 14 并注明原因，分数按已计分的权重归一，不按 0 分扣。
  3. 每分都能追到规则。点开"先改这三条"，每条都带规则号、扣了多少、为什么、怎么改、来源。
这是本项目自定义的加权分，不是亚马逊官方评分（官方没有公开的 Listing 分），也不预测排名或流量。界面上原话写着这句，改文案时别删。

18.2 评论分析（VOC，数据采集页）

书签脚本在商品页会顺手抓当前这一页的评论（默认 10 条，最多 20 条），粘回来就能看到：

  • 痛点簇：按"低星提及数"排序，带低星平均星级和低星原话（不会拿一句 5 星好评当抱怨）
  • 好评簇：4–5 星里被提到的方面 —— 这些词可以直接搬进五点
  • 高频疑问：评论里真有人问的问题，说明详情页没答
  • 词频线索：只当线索，不是关键词建议

边界写在卡片底部的折叠块里：只分析抓到的样本、按"最有帮助"排序天然带偏、聚类靠词表（14 个方面）、不推断原因。样本少于 5 条只说"线索"，不给百分比结论。

图片库每张图多了「体检」按钮，也可以直接上传任意一张本地图。全部在浏览器里读像素，图片不上传。

18.4 历史快照与迷你趋势图（数据采集页）

采集到某个 ASIN 后点「记一条快照」，会写进本机 data/snapshots/<ASIN>.jsonl（一行一个 JSON）。下次再记，就能看到价格 / 星级 / 评论数 / 类目排名四条小趋势。

三个刻意设计：

  • 值没变就不写。同一份数据点两次，第二次不落盘，并告诉你原因 —— 否则趋势图上会出现一串完全相同的点。
  • 不插值。中间缺数据就断开，绝不把相隔一个月的两点连成一条假曲线。
  • 不预测。两个点才画；只有 1 条时直接说"一个点画不出趋势"。

18.5 可选插件：本地抠图（设置页）

本项目不打包模型（rembg 要 Python + onnxruntime，几百 MB）。想用就自己在本机起一个 rembg 服务，在 .env.local 写：

REMBG_URL=http://127.0.0.1:7000/api/remove

重启服务后，图片库每张图会多一个「抠图」按钮，结果存进 data/gen/。
目标地址只允许本机或私网（127.0.0.1 / localhost / ::1 / 10.x / 192.168.x / 172.16–31.x）—— 这个代理是服务端代发请求，不限制就是 SSRF 跳板。没配时接口明确回 not-configured，界面显示"未启用"，不假装有这个功能。

十九、A+ 骨架 / 批量质检 / 第三方词表

这三块解决的是同一类问题：单条流程走通之后，真实工作里还会卡住的地方。

19.1 A+ 内容模块骨架（文案与质检页 → 抽屉 ⑧）

品牌备案之后才有 A+。多数人卡在"打开编辑器，三栏空白，不知道先写哪句"。
这一步给三块模块的结构、写作预算与配图提示词，内容从你已经在上面填好的品牌 / 产品名 / 卖点派生。

模块它负责回答结构
品牌故事你是谁、为什么做这个标题 + 副标题 + 正文（三张卡片图）
对比表我这款和别的型号差在哪表头 + 6 个维度（本品 + 最多 5 个竞品）
模块网格让不看字的人也能懂三格，每格一个小标题 + 一句说明

三条边界，界面上也这么写：

  1. 字数预算是本工具的建议值，用来防"一句话写 400 字"；各模块字段的硬限制以模块编辑页显示的计数为准。本工具不冒充官方值。
  2. 只出骨架，不出可提交的模块代码、不生成图片。后台编辑器只认它自己的字段，任何"导出即上传"的说法都是假的。
  3. A+ 里的文字同样受 Listing 的合规约束。自检直接复用 listing.js 的促销词 / 声明词 / 特殊符号表，外加 A+ 特有的四类高风险表述：

价格与促销（会过期）、贬低竞品、排名与畅销宣称、绝对化承诺。

缺品牌名或卖点时，对应位置写 【待填】 并在顶部列出缺什么 —— 不替你编一个品牌故事。

19.2 批量质检（文案与质检页 → 抽屉 ⑨）

单条质检回答"这条行不行"，批量回答"我 20 条里先改哪条"。

输入格式（两种都认，一次最多 30 条）：

B0ABC12345
Premium Ceramic Mug 350ml Double Wall Insulated ...
- 保温 6 小时
- 304 不锈钢
---
标题：Montessori Busy Board for Toddlers 1-3
五点：
- 安全毛毡，无锐边
- 可带上飞机

排序规则是刻意的：先按"有没有命中硬规则（P 级）"，再按分数。
一条 92 分但标题超限（P1）的链接，比 78 分全是软规则的更急 —— 只按分数排会把最急的那条排到中间。

口径必须说清：批量模式只有标题 + 五点，缺 Item Highlights、Search Terms、Rufus 字段与覆盖度，
所以出的是同口径的部分维度分（权重 61/100，其余按归一）。行与行之间可比，
但不要拿它和单条页面上的健康分比大小。界面上这句话原样写着。

解析不出来的块报错并跳过，不拿第一行五点冒充标题；条数超限直接报错，不静默截断。
汇总可导出 CSV（带 BOM，Excel 打开不乱码）。

19.3 第三方关键词 CSV 导入（文案与质检页 → 取词区）

卖家精灵 / Helium 10 / Jungle Scout 都能导出"关键词 + 搜索量"。本工具不自己算、也不估搜索量，
但你导出的数据应当能直接用，否则只能手工敲几百个词。

能识别的表头例子
关键词Keyword Phrase / Search Term / Keyword / 关键词 / 搜索词
搜索量Search Volume / Est. Searches / 月搜索量(精确) / 搜索热度
ASIN只认精确的 ASIN / Child ASIN（不认 Sponsored ASINs）

处理细节：

  • 分隔符自动嗅探：逗号 / 分号 / 制表符都认（欧洲区 Excel 默认分号，从表格复制过来常是制表符）。
  • 搜索量解析：1,200 / 12K / 1.2万 都能读；读不出来留空并记原因，不填 0（0 会被读成"没人搜"）。
  • 重复词保留搜索量更大的那条。
  • 千分位逗号没加引号（保温杯,8,500）会把搜索量读成 8 —— 这种行标成"存疑"、界面显示 ?，并提示重导，不假装读对了。
  • 不猜列：找不到关键词列就报错并列出实际表头。猜错会把 ASIN 当关键词，然后整张覆盖表全红。

导入后点「把这批词填进自定义关键词」（按搜索量取前 200 个），再跑覆盖度分析，
表里会多一列搜索量。这一列只用于排序取舍，不参与覆盖判定；表下会标"来自你导入的 xxx.csv，不是本工具估算的"。
