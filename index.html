语种边界：哪些语种能判、哪些会标成「未覆盖」

德国站标题里满篇 mit / für / und，不切语种就会把它们当成卖点关键词。词频与停用词支持 中/英/德/法/西/意/荷/日 7 套； 利益词判据（C3）有 中 / 英 / 德 / 日 4 套（德语必须在这里显式选中 —— 拉丁字母单看字形会被当成英文）； 法 / 西 / 意 / 荷 没有利益词表，会明确标成「未覆盖·跳过」，不会拿英文词表硬套。 Prompt 输出仍只有中文、英文两套。

体检结果

未命中的规则也会列出，方便你看见「检查过什么」。

⑥ Rufus 信息架构检查准入层 · 能不能被纳进结构化比对

⑤ 查「文案合不合规」，这一层查「能不能被纳入结构化比对」：必填字段有没有空、跨字段事实有没有矛盾、同一维度有没有两套单位制、买家高频问题有没有答案句、图里的字有没有文本化。不做 OCR、不猜图上内容；跳过项一律列出来并说明原因。

Rufus / Alexa+ 是什么关系、能力边界

Rufus / Alexa for Shopping 的机制是先做结构化比对、再决定要不要引用你的文案。2025 年起亚马逊把购物助手逐步收进 Alexa+ 品牌， 两个名字指同一类能力，但本工具不宣称二者功能完全等同（官方更名公告原文未取得，按待核实处理）。

能力边界：这是一套基于公开字段规范与帮助文档的启发式检查，不是官方评分，也不预测排名或流量。跑完没红 ≠ 平台会给流量。

结论只有一条，来自引擎的 summary.conclusion。
⑦ 竞品关键词 → 文案提示词从 Best Sellers 实时抓标题 → 本地算权重

从亚马逊 Best Sellers 公开榜单页实时抓竞品标题 → 本地算关键词权重（覆盖率×50% + 位置×30% + 精准度×20%）→ 生成可复制的文案提示词。 ⚠️ 亚马逊改页面结构时会抓不到（如实报错，不会静默给假数据）；带 10 分钟缓存。原「关键词搜索」路径（/s?k=）已被封锁，本工作台不提供。

权重 = 覆盖率 × 50% + 位置 × 30% + 精准度 × 20%，满分 10 分。只保留出现 ≥2 条的词（出现 1 次的是噪声）。

提示词里只带工具算好的结论，并明确要求模型「直接采用、不要重算」。
⑧ A+ 内容模块骨架品牌故事 / 对比表 / 模块网格 + 配图提示词

品牌备案后才有 A+。这里给三块模块的结构、写作预算与配图提示词，内容从上面「产品与语料」里的品牌 / 产品名 / 卖点派生 —— 不是通用模板。 不生成可直接提交的模块代码、不生成图片：后台编辑器只认它自己的字段，任何「导出即上传」的说法都是假的。

读的是「产品与语料」里的品牌 / 产品名 / 卖点
⑨ 批量质检多条 listing 一次粘进来 → 按「先改哪条」排序

单条质检回答「这条行不行」，批量回答「我 20 条里先改哪条」。每块第一行是标题、其余行是五点，块之间用一行 --- 分隔； 也可以在块首写 B0XXXXXXXX 或 标题： / 五点： 标签。一次最多 30 条。

启动方式

            
cd 跨境Listing优化工作台
node server.mjs
# 浏览器打开 http://127.0.0.1:8787/

            
⚠️ 不要双击 index.html。本应用是 ES 模块，浏览器会以 CORS 为由拦掉 file:// 下的模块请求，页面会是一张空壳（实测：file:// 下 JS 一行都没跑）。必须通过 node server.mjs 打开。

            没配图片 API 也能用全部本地能力（模板库 / Prompt 引擎 / Listing 质检 / 采集解析），只是不能真出图。
