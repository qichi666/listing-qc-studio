# 测试盲区清单

> 写这份东西的原因：**842 条断言全绿，很容易被读成"这个工具是对的"。**
> 它不是。断言只证明"这些具体行为没坏"，不证明"规则本身符合亚马逊官方规则"，
> 也不证明"在别人的机器上、别人的网络里、别人的数据下同样成立"。
> 把没测的部分写下来，是为了让"全绿"这个词有边界 —— 和界面里那些 `externals` 一个道理。

**当前基线（2026-11-07）**

| 套件 | 条数 | 跑什么 | 不跑什么 |
|---|---:|---|---|
| `tools/selftest.mjs` | 509 | 纯函数行为：规则、Prompt、导出、状态语义、快照对比、语种边界 | 不碰真实数据、不发网络请求 |
| `tools/verify-server.mjs` | 211 | 服务端契约：只读门、断连取消、资源闸门、IP 钉死、配置写盘、词库读接口 | 用 mock 上游，不打真实生图/LLM 接口 |
| `tools/browser-selftest.mjs` | 122 | 真实 Chrome：IndexedDB、DOM 交互、下拉替身、CSV 导出、词库四态 / 体检卡文案 | 只测"点完 DOM 里有什么"，不测像素 |
| `tools/mcp-selftest.mjs` | 175 | MCP 协议往返：stdout 纯度、8 个工具契约、配置可用、`data/` 未写 | 不覆盖真实客户端（Claude Desktop / Cursor）的加载行为 |
| `tools/keywords-selftest.mjs` | 111 | 词根表、合并口径、ASIN 字段对齐、陈旧四态、**采集器 dry-run 实跑**、状态文件与文件锁 | **不真去抓亚马逊**（真实采集在 Actions 里跑） |

前三套是产品回归（合计 842），后两套单列 —— 口径见 `tools/expected-counts.json`。
三套**必须顺序跑**（并行会互相把对方的报告文件当变动）。条数由
`tools/expected-counts.json` + `tools/assert-count.mjs` 守住：**少了算失败，多了只提示**。

## 一、按"坏了会怎样"排序的盲区

### B1 · 亚马逊页面结构变更（最可能先坏的一条）

- **现状**：`browser-selftest` 里抓取那一段，**允许失败**（亚马逊改结构 / 断网 / 限流都算正常环境），
  断言的是"两种结局都诚实"——抓到就给数据，抓不到就明确说失败页，不许假装成功。
- **盲区**：选择器（`#productTitle` / `#feature-bullets` …）**真的失效**时，测试不会红，
  只会表现为"抓到 0 条 / 缺字段"。这是刻意的取舍：把不可控的外部站点写进断言，
  得到的是随机红，而随机红会训练人忽略红色。
- **你会看到什么**：采集卡显示"抓到 0 个商品"或字段大片空白，而不是报错。
- **怎么补**：存一份真实页面 HTML 做 fixture（脱敏），离线跑解析断言。成本：约 30 分钟 +
  每次亚马逊改版要重新存一份。**没做，因为 fixture 会过期，过期后比没有更误导。**

### B2 · 真实外部 API 的返回漂移

- **现状**：生图 / LLM / Vision 全部打 **mock 上游**（`verify-server.mjs` 里起的本地服务）。
- **盲区**：真实接口的限流码、异步任务的 `task_id` 结构、返回图片的 content-type、
  同步接口的分辨率白名单变化 —— 都在 mock 里被"理想化"了。
  画幅吸附逻辑测的是**我们发什么**，不是**对方收不收**。
- **你会看到什么**：出图报错信息里出现没见过的状态码；或图出来了但比例跟 `sizeNote` 说的不一致。
- **怎么补**：用真 Key 跑一次冒烟（人工，不进门禁）。**成本 = 一次调用费，所以不进 CI。**

### B3 · IndexedDB 的真实边界

- **现状**：测了 save → list → get → stats → remove、裁剪标记、按类清空、导入导出往返。
- **盲区**：① 配额耗尽（`QuotaExceededError`）只写了 catch，没真跑过；
  ② 多标签页并发写（两个窗口同时往里塞）没有锁，最后写入者赢；
  ③ 隐私模式 / 老浏览器的降级**只在代码注释里**，没在真实受限环境验证。
- **你会看到什么**：① 保存静默失败或提示"当前环境存不了"；② 历史列表偶尔少几条。
- **怎么补**：① 可以补（往库里塞到爆，成本 20 分钟）；② 需要设计决定（要不要加锁），
  当前判断是**不值得**——这是一个单人本地工具，两个标签页同时写属于误用。

### B4 · 规则本身的正确性（最重要，也最不可能靠断言解决）

- **现状**：580 条断言证明"给定输入 → 给定结论"，**不证明结论符合平台规则**。
- **明确标了「待核实」的两条**（`AMAZON_MAIN_IMAGE.sourceTier`）：
  - 主图禁 AI 生成 —— 由官方两条（主图须为摄影作品、图片须如实代表商品）**合并推论**得出，
    专项原文未取得；
  - XMP / IPTC 打标 —— 来自 IPTC / C2PA 行业规范，亚马逊是否强校验未取得官方原文。
- **其他边界**：
  - 日文**纯汉字**标题与中文无法区分（`detectScript` 会判 `zh`）—— 写明的已知边界；
  - 德语复合词（`KaffeetassenSet`）不会被拆成 `Kaffee` + `Tasse`；
  - 法语省音（`l'eau`）与意大利语缩合（`dell'acqua`）分词未验证；
  - 停用词表是**人工整理**的，不是官方词表。
- **你会看到什么**：工具说"通过"，平台上仍被拒或被改。
- **怎么补**：拿到官方原文才能补。**在那之前，"通过"只等于"没命中我们知道的规则"。**

### B5 · 界面只测结构，不测视觉与可达性

- **现状**：`browser-selftest` 断言"点了按钮 → DOM 里出现某段文字/某个元素"。
- **盲区**：像素级样式、深色模式、1440/1920 宽度下的换行、移动端布局、
  键盘 Tab 顺序、屏幕阅读器朗读、颜色对比度。
- **你会看到什么**：功能都在，但窄屏挤压、或键盘走不到某个按钮。
- **怎么补**：视觉回归要引截图比对（会引依赖，违背"零依赖"）；可达性可以用
  `axe-core` 跑一次（一次性，不进门禁）。**当前没做。**

### B6 · 浏览器矩阵

- **现状**：只跑本机一个 Chromium（`--headless=new`）。
- **盲区**：Safari（IndexedDB 实现差异、`crypto.randomUUID` 可用性）、
  Firefox（`select` 替身的位置计算）、iOS Safari（`confirm` 行为、下载 API）。
- **你会看到什么**：某个浏览器里导入/导出或下载不工作。
- **怎么补**：Playwright 多引擎是正路，但会引依赖。**当前判断：不做。**

### B7 · 服务端只读门只覆盖"已知的写路由"

- **现状**：线上演示版（`LISTING_NO_KEY_WRITE=1`）按白名单关掉 6 条写路由，其余放行；
  `/api/chat` 刻意留在门外（在线体验主链路，不花额度）。
- **盲区**：新增一条写路由但忘了加进白名单 → 线上变成可写。
- **你会看到什么**：线上演示环境里磁盘多出文件，或额度被消耗。
- **怎么补**：`verify-server.mjs` 已按"名单"断言，但名单本身要人工维护。
  更稳的做法是**改成默认拒绝**（只放行读路由），代价是每加一个读接口都要登记。
  **未改，因为当前路由表稳定，默认拒绝的维护成本更高。**

### B8 · 没有账号体系，所以没有"越权"这一类测试

- **说明**：本工具**设计上就是单用户本地工具**（线上演示版是只读、无登录的公开页）。
  没有用户表、没有会话、没有多租户数据隔离 —— 因此"横向越权 / 纵向越权"这类测试**不适用**，
  不是漏测。审阅时请注意别把"没有权限测试"当成"权限没做对"。
- **唯一相关的**：`Host` 头白名单（挡 DNS rebinding）、静态服务白名单（只放行
  `index.html` 与 `assets/`）、上传魔数嗅探（挡 SVG 里的 `<script>` 同源 XSS）、
  出网 IP 钉死（挡 SSRF + rebinding）。这四条都有断言。

### B9 · 成本相关行为只测了"拦一下"，没测"真扣钱"

- 整套逐张出图：测了"必须先 confirm、串行、可停、失败不中断、开跑前提示按你自己的接口计费"。
- **没测也不该测**的是：真的扣了多少钱、中途失败时对方是否已计费。
  这些只能在你的账单里看，工具不代你估算 —— 界面上也是这么写的。

### B10 · 每周词库：测的是"流程没坏"，不是"数据对"

- **测到的**：词根表结构合法、合并口径（`firstSeen` 继承 / `hits` 归并 / 上限截断必写 `note`）、
  陈旧三态（`fresh` / `stale` / `missing`）、**采集器 dry-run 真跑一遍临时目录**、
  「一条都没抓到就不写盘」、以及 MCP 与采集器**共用同一份** `amazon-suggest.js`（源码级反向锁）。
- **没测也不该测**：
  - **词是不是"对的"** —— 建议词只说明有人这么打，与你的品类是否相关是**人的判断**，断言写不出来；
  - **搜索量** —— 拿不到，也就无从断言（这是本工具唯一没有量化热度的地方）；
  - **真实抓取的成功率** —— 亚马逊随时改版/限流，写成"必须 ≥N 条"只会随机红；
    所以线上跑在 Actions 里，**失败会红、但不会拿空数据盖掉上一份好的**。
- **已知会漂的**：`rank` 是榜单名次，会随榜单刷新变化；`hits` 只代表这周被几个词根带出来，
  与搜索热度无关。**同一词根两次调用建议接口，返回的词面可能不一样**（第 1→2 轮有 211 条没再出现，
  第 2→3 轮却完全一致），所以「本周新增 / 消失」是粗信号，不是趋势。两者都不该被当成趋势指标。

## 二、明确"不做"的清单（免得以后被当成遗漏）

| 不做的事 | 理由 |
|---|---|
| 真实上传到亚马逊后台 | 无公开 API 权限，也不该由测试脚本碰真实店铺 |
| 像素级视觉回归 | 要引截图比对依赖，违背零 npm 依赖 |
| 跨浏览器矩阵进 CI | 同上；且本工具的使用场景是"自己电脑上开一个页面" |
| 用真实 API Key 跑门禁 | 每次跑都花钱，且会把密钥写进 CI 环境 |
| 抓取结果的"必须 ≥N 条"断言 | 亚马逊随时改版/限流，这种断言只会随机红 |
| 账号 / 权限体系测试 | 设计上没有账号体系（见 B8） |

## 三、怎么加一条新断言

1. 断言**行为**，不断言实现：`composePrompt(...)` 的输出里有没有那串约束，而不是"函数第 3 行写了什么"。
2. 静态断言（读源码正则）只在"防止同一事实出现第二份实现"时用，且**必须过滤注释行**
   （`codeOf()`）——否则解释缺陷的注释会被判成缺陷仍在。
3. 新行为要**双向测**：「变了必须写」和「没变不准写」都要断言，否则会静默吞掉有效写入。
4. 跑完把 `tools/expected-counts.json` 的数字调上去；**不要往下调**（下调 = 有断言被删了）。
5. 顺序跑三套：`selftest` → `verify-server` → `browser-selftest`。
